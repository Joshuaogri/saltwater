## Storage observation

- Empty disposable database after 0001+0002 and rolled-back acceptance fixtures: **8,756,247 bytes** = **8.756 MB** decimal = **8.351 MiB**.
- After 1,000 synthetic people, each with one canonical profile-history row, one population-state row, one population-history row and two linked event rows: **9,706,519 bytes** = **9.707 MB** decimal = **9.257 MiB**; growth **950,272 bytes** (0.950 MB; 0.906 MiB).
- After filling the same compact structure to the hard cap of 10,000 people: **16,948,247 bytes** = **16.948 MB** decimal = **16.164 MiB**; growth over the post-migration baseline **8,192,000 bytes** = **8.192 MB** = **7.8125 MiB**, or **819.2 bytes per person** averaged over the full fixture.
- The 1,000-person and 10,000-person averages differ because PostgreSQL allocates storage in pages and indexes; use the full-cap run as the stronger compact-fixture baseline, not as a universal per-person constant.
- This is an observed disposable PostgreSQL 16.16 measurement for the specified compact fixture, not a production/Neon estimate. It excludes residence, relationships, jobs, police dossiers, case records, richer event attributes, narrative text, indexes introduced by later divisions, and long-run bloat.
- A clean pre-0001 database baseline and isolated 0001-vs-0002 deltas were not captured. No production capacity conclusion follows.
